    用CUDA实现MHA的FlashAttention V1/V2¶

    学习目标¶

    • 理解FlashAttention V1/V2的完整算法
    • 对比测试执行速度和显存占用

    1. FlashAttention V1完整版本¶

    之前我们的Debug版本的代码主要用于测试和学习，里面的维度都是固定的且非常小：

    #define BR 3    // Q 的分块大小 (Row Block)
#define BC 2    // K, V 的分块大小 (Col Block)
#define D 2     // Head Dimension (hidden_dim)

    现在我们需要把它修改成实际场景的大小。

    而且我们之前的Attention计算只考虑一个头，我们需要实现多头注意力(Multi-Head Attention)。

    另外为了让代码可以适配各种输入的形状，我们把共享变量从静态声明变成动态声明。完整的代码在flash-attn-cpp/flash-attn_v1.cu。我们这里把它分解成不同的部分来学习。

    1.1 定义常量¶

    #define D_MAX 512
#define BC_MAX 256

    因为我们需要在函数内部定义float o_i[D_MAX]、float S_ij[BC_MAX]和float P_tilde_ij[BC_MAX]，所以需要定义最大的大小。

    1.2 启动Kernel的包装函数¶

    // C++ 包装函数，支持动态参数传入
torch::Tensor flash_attn_v1_mha_forward(
    torch::Tensor Q, 
    torch::Tensor K, 
    torch::Tensor V,
    int BR,
    int BC
) {
    // 运行时从 Tensor 维度获取 B, H, N, D
    const int B = Q.size(0);
    const int H = Q.size(1);
    const int N = Q.size(2);
    const int D = Q.size(3);

    auto O = torch::zeros_like(Q);
    auto M = torch::full({B, H, N}, -FLT_MAX, Q.options());
    auto L = torch::zeros({B, H, N}, Q.options());

    // Grid 维度: (1, Head数, Batch数)
    dim3 grid_size(1, H, B);
    dim3 block_size(BR);

    // 2. 动态计算共享内存的字节数 (BC*D + BC*D + BR*D) * sizeof(float)
    size_t smem_size = (2 * BC * D + BR * D) * sizeof(float);

    const float softmax_scale = 1.0f / std::sqrt(static_cast<float>(D));

    cudaStream_t stream = c10::cuda::getCurrentCUDAStream();

    // 3. 动态配置 Kernel 启动参数 <<<grid, block, smem_size, stream>>>
    flash_attn_v1_mha_kernel<<<grid_size, block_size, smem_size, stream>>>(
        Q.data_ptr<float>(),
        K.data_ptr<float>(),
        V.data_ptr<float>(),
        O.data_ptr<float>(),
        L.data_ptr<float>(),
        M.data_ptr<float>(),
        N, D, BR, BC,
        softmax_scale
    );

    return O;
}

    1.2.1. 函数签名与参数¶

    torch::Tensor flash_attn_v1_mha_forward(
    torch::Tensor Q, 
    torch::Tensor K, 
    torch::Tensor V,
    int BR,
    int BC
)
    • Q, K, V: 输入的 PyTorch 张量（Tensor），分别代表 Query、Key 和 Value。
    • BR, BC: FlashAttention 分块（Tiling）算法中的块大小（Block Size）。BR 是行分块大小（对应 Q 的序列长度维度），BC 是列分块大小（对应 K/V 的序列长度维度）。
    • 返回值: 返回一个 torch::Tensor，即注意力机制的输出矩阵 O。

    1.2.2. 维度解析与张量初始化¶

    const int B = Q.size(0); // Batch Size (批次大小)
const int H = Q.size(1); // Num Heads (注意力头数)
const int N = Q.size(2); // Sequence Length (序列长度)
const int D = Q.size(3); // Head Dimension (每个头的维度)

auto O = torch::zeros_like(Q);
auto M = torch::full({B, H, N}, -FLT_MAX, Q.options());
auto L = torch::zeros({B, H, N}, Q.options());
    • 维度获取: 从输入张量 Q 中动态解析出 FlashAttention 所需的关键维度：Batch大小 B、头数 H、序列长度 N 和头维度 D。标准输入形状通常为 [Batch, Head, SeqLen, HeadDim]。
    • O (Output): 初始化一个与 Q 形状相同、全零的张量，用于存放最终的注意力输出。
    • M (Log-sum-exp 统计量): 初始化大小为 [B, H, N] 的张量，填充为负无穷（-FLT_MAX），用于在线 Softmax（Online Softmax）算法中存储中间的最大值。
    • L (Scaling 因子): 初始化大小为 [B, H, N] 的全零张量，用于存储在线 Softmax 的分母累加和（Normalization Factor）。

    1.2.3. CUDA 执行配置（Grid 与 Block）¶

    dim3 grid_size(1, H, B);
dim3 block_size(BR);
    • block_size(BR): 线程块（Thread Block）的大小设为 BR。意味着每个 CUDA Block 包含 BR 个线程，它们协作处理 Q 的一个分块。
    • grid_size(1, H, B): 网格大小是一个三维结构：
      • x = 1: 和之前一样，一个线程块处理所有行。
      • y = H: 每一个 Head 分配一个独立的行方向任务。
      • z = B: 每一个 Batch 分配一个独立的任务。
      • 这种设计使得每个 CUDA Block 可以独立处理特定 Batch、特定 Head 的计算。

    1.2.4. 动态共享内存（Shared Memory）计算¶

    size_t smem_size = (2 * BC * D + BR * D) * sizeof(float);
    • FlashAttention 的核心优化之一是利用 GPU 的高速共享内存（SRAM）减少对全局显存（HBM）的访问。
    • 这行代码动态计算了本次 Kernel 启动所需要的共享内存字节数：
      • 2 * BC * D: 用于同时缓存 K 和 V 的分块数据（大小均为 BC \times D）。
      • BR * D: 用于缓存 Q 的分块数据（大小为 BR \times D）。
      • 乘以 sizeof(float) 转换为总字节数。这个大小时刻在 Kernel 启动时通过第三个尖括号参数传递给硬件。

    1.2.5. 缩放因子与流管理¶

    const float softmax_scale = 1.0f / std::sqrt(static_cast<float>(D));

cudaStream_t stream = c10::cuda::getCurrentCUDAStream();
    • softmax_scale: 计算注意力得分时的缩放系数 \frac{1}{\sqrt{d_k}}，防止点积结果随维度 D 增大而过大，导致 Softmax 函数梯度弥散。
    • stream: 获取当前 PyTorch 正在使用的 CUDA 流（Stream），确保该算子的执行能够与 PyTorch 其他算子正确异步并发或排队。

    1.2.6. 启动 CUDA Kernel¶

    flash_attn_v1_mha_kernel<<<grid_size, block_size, smem_size, stream>>>(
    Q.data_ptr<float>(),
    K.data_ptr<float>(),
    V.data_ptr<float>(),
    O.data_ptr<float>(),
    L.data_ptr<float>(),
    M.data_ptr<float>(),
    N, D, BR, BC,
    softmax_scale
);
    • 使用 CUDA 的三重尖括号语法 <<<grid, block, smem_size, stream>>> 启动底层编写的 flash_attn_v1_mha_kernel 核函数。
    • 通过 .data_ptr<float>() 将 PyTorch 的 torch::Tensor 转换为原生的 C++ float* 指针，传递给 GPU 端进行指针寻址和高速计算。

    整个包装函数起到了承上启下的作用：向上 对接 PyTorch 的张量管理、内存分配与自动求导上下文；向下 配置好 GPU 的硬件执行参数（Grid、Block、Shared Memory、Stream），并驱动底层 CUDA Kernel 高效完成多头注意力计算。

    1.3 函数原型¶

    // 动态 Shared Memory 版 FlashAttention-v1 Alg1 MHA Kernel
__global__ void flash_attn_v1_mha_kernel(
    const float* __restrict__ Q, // [B, H, N, D]
    const float* __restrict__ K, // [B, H, N, D]
    const float* __restrict__ V, // [B, H, N, D]
    float* __restrict__ O,       // [B, H, N, D]
    float* __restrict__ L,       // [B, H, N]
    float* __restrict__ M,       // [B, H, N]
    const int N,
    const int D,
    const int BR,
    const int BC,
    const float softmax_scale
) {
    const int tid = threadIdx.x; // blockDim.x = BR

    // 每一个 Block 处理一个特定的 (batch_idx, head_idx)
    const int head_idx = blockIdx.y;
    const int batch_idx = blockIdx.z;
    • tid (Thread ID): 获取当前线程在 Block 内的局部一维编号。因为在包装函数中配置 block_size(BR)，所以 blockDim.x 等于 BR，tid 的取值范围是 0 到 BR - 1。
    • head_idx 和 batch_idx: 对应包装函数中配置的 grid_size(1, H, B)：
    • blockIdx.y 对应当前 Block 负责的注意力头索引（0 到 H-1）。
    • blockIdx.z 对应当前 Block 负责的批次索引（0 到 B-1）。
    • 并行架构对应关系: 每一个 CUDA Block 独占一个特定的 (batch_idx, head_idx) 组合，并在内部通过 BR 个线程并行计算该 Head 下的注意力分块。

    1.4 动态共享内存分配¶

        // 1. 动态 Shared Memory 布局划分
    // 布局结构: k_smem [BC * D] -> v_smem [BC * D] -> q_smem [BR * D]
    extern __shared__ float smem[];
    float* k_smem = smem;
    float* v_smem = k_smem + BC * D;
    float* q_smem = v_smem + BC * D;

    这段代码展示了在 CUDA 核函数中如何对动态共享内存（Dynamic Shared Memory）进行线性划分。由于在主机端启动 Kernel 时传入了总字节数 smem_size，在这里通过 extern __shared__ 声明了一个未指定大小的外部共享内存数组，并将其划分为三个不同用途的逻辑子缓冲区。

    1.4.1. 动态共享内存声明¶

    extern __shared__ float smem[];
    • extern __shared__: 告诉编译器这块共享内存的大小在编译期未知，而是在运行时由主机端启动 Kernel 时（即 <<<grid, block, smem_size, stream>>> 中的第三个参数）动态指定的。
    • float smem[]: 声明为一个 float 类型的浮点数指针（数组形式），作为整个共享内存块的基地址。

    1.4.2. 共享内存布局划分¶

    紧接着的三行代码通过指针偏移量，将这块连续的共享内存切分成了三个独立的数据缓存区：

    float* k_smem = smem;
float* v_smem = k_smem + BC * D;
float* q_smem = v_smem + BC * D;
    • k_smem (Key 缓存区):
      • 起始于整个共享内存的头部（smem）。
      • 大小为 BC \times D 个 float，用于从全局显存（HBM）中加载并缓存当前 K 矩阵的一个分块（包含 BC 个 Token，每个 Token 维度为 D）。
    • v_smem (Value 缓存区):
      • 紧跟在 k_smem 后面，起始地址为 k_smem + BC * D。
      • 大小同样为 BC \times D 个 float，用于缓存 V 矩阵的一个分块。
    • q_smem (Query 缓存区):
      • 位于整个共享内存的最末端，起始地址为 v_smem + BC * D（即 smem + 2 * BC * D）。
      • 大小为 BR \times D 个 float（对应 BR 个 Query 线程，每个线程持有维度为 D 的数据），用于缓存当前 Block 负责的 Q 矩阵分块。

    1.4.3 这种布局设计的意义¶

    FlashAttention 的核心在于 分块计算（Tiling），通过把全局显存（HBM）中的大矩阵分块加载到速度极快的片上共享内存（SRAM / Shared Memory）中，可以大幅减少访存延迟并提高算力利用率。这种指针偏移的划分方式高效且安全，确保了三个矩阵在同一块共享内存中井水不犯河水，匹配前面在 C++ 包装函数中计算的 smem_size = (2 * BC * D + BR * D) * sizeof(float) 总大小。

    1.5 计算偏移量¶

        // 当前 Batch 和 Head 在 HBM 中的基地址偏移
    const int bh_offset = (batch_idx * gridDim.y + head_idx) * N * D;
    const int bh_l_offset = (batch_idx * gridDim.y + head_idx) * N;

    const float* Q_head = Q + bh_offset;
    const float* K_head = K + bh_offset;
    const float* V_head = V + bh_offset;
    float* O_head = O + bh_offset;
    float* L_head = L + bh_l_offset;
    float* M_head = M + bh_l_offset;

    1.5.1. 4D 张量偏移量计算 (bh_offset)¶

    const int bh_offset = (batch_idx * gridDim.y + head_idx) * N * D;
    • 作用: 为形状为 [B, H, N, D] 的 4D 张量（如 Q, K, V, O）计算一维线性内存的起始偏移量。
    • 计算逻辑:
      • batch_idx * gridDim.y + head_idx（其中 gridDim.y = H）相当于将 Batch 和 Head 维度展平，计算出当前是第几个 Head-Batch 组合。
      • 乘以 N * D 是因为每一个 Head 包含 N 个 Token，每个 Token 有 D 维。

    1.5.2. 3D 张量偏移量计算 (bh_l_offset)¶

    const int bh_l_offset = (batch_idx * gridDim.y + head_idx) * N;
    • 作用: 为形状为 [B, H, N] 的 3D 辅助统计量张量（如 L, M）计算偏移量。
    • 计算逻辑: 因为 L 和 M 的维度是 [B, H, N]（没有最后的 D 维度），所以每个 Head 只需要 N 个元素的空间，这里乘以 N 即可定位到当前 Head 的起始位置。

    1.5.3. 指针平移（获取当前 Head 的专属视图）¶

    const float* Q_head = Q + bh_offset;
const float* K_head = K + bh_offset;
const float* V_head = V + bh_offset;
float* O_head = O + bh_offset;
float* L_head = L + bh_l_offset;
float* M_head = M + bh_l_offset;
    • 通过将全局大矩阵的基指针（如 Q）加上刚才计算好的偏移量（bh_offset 或 bh_l_offset），得到 Q_head、K_head 等指针。
    • 意义: 经过这一步后，当前 CUDA Block 内部的所有线程就可以直接把 Q_head 等当作“属于当前 Batch 和 Head 的独立矩阵”来访问，简化了后续代码中的多维寻址逻辑。

    1.5.4 简单示例¶

    假设我们有一个非常小的 4D 张量（如 Q），其维度参数如下：

    • B (Batch Size) = 2
    • H (Num Heads) = 2
    • N (Sequence Length) = 4
    • D (Head Dimension) = 2

    整个张量在内存中的总元素个数为 2 \times 2 \times 4 \times 2 = 32 个 float。

    现在，我们来看其中某一个特定的 Block：

    • blockIdx.z = 1 \rightarrow batch_idx = 1（处理第 2 个 Batch）
    • blockIdx.y = 0 \rightarrow head_idx = 0（处理第 1 个 Head）

    1.5.4.1. 计算 4D 张量的显存偏移量 (bh_offset)¶

    公式：

    \text{bh_offset} = (\text{batch_idx} \times \text{gridDim.y} + \text{head_idx}) \times N \times D

    代入具体数字：

    \text{bh_offset} = (1 \times 2 + 0) \times 4 \times 2 = 2 \times 8 = 16
    • 结果含义：当前 Block 负责的 Batch 1, Head 0，其数据在全局显存（HBM）的一维线性空间中，从第 16 个 float 开始。
    • 物理位置映射：整个 32 个元素的张量按 [B, H, N, D] 排布：
      • Batch 0, Head 0: 元素 0 ~ 7
      • Batch 0, Head 1: 元素 8 ~ 15
      • Batch 1, Head 0: 元素 16 ~ 23 \leftarrow Q_head 指向这里
      • Batch 1, Head 1: 元素 24 ~ 31
    1.5.4.2. 计算 3D 辅助张量的显存偏移量 (bh_l_offset)¶

    对于形状为 [B, H, N] 的辅助张量（如 L 和 M），总大小为 2 \times 2 \times 4 = 16 个 float。

    公式：

    \text{bh_l_offset} = (\text{batch_idx} \times \text{gridDim.y} + \text{head_idx}) \times N

    代入具体数字：

    \text{bh_l_offset} = (1 \times 2 + 0) \times 4 = 2 \times 4 = 8
    • 结果含义：对于 L 和 M 张量，当前 Batch 1, Head 0 的统计量从第 8 个 float 开始。
    • 物理位置映射：
      • Batch 0, Head 0: 元素 0 ~ 3
      • Batch 0, Head 1: 元素 4 ~ 7
      • Batch 1, Head 0: 元素 8 ~ 11 \leftarrow L_head / M_head 指向这里
      • Batch 1, Head 1: 元素 12 ~ 15

    1.13.1. 配置输出与张量初始化¶

    torch::NoGradGuard no_grad;
...

    • torch::NoGradGuard: 关闭 PyTorch 的自动求导（Autograd）引擎。因为在测试推理（Forward）性能和正确性时不需要计算梯度，关闭它可以节省显存并避免不必要的开销。
    • 输入张量生成: 在 GPU（torch::kCUDA）上随机生成了标准正态分布的 Q、K、V 张量，数据类型为 32 位浮点数（float32）。

    torch::NoGradGuard 是 C++ 中应用 RAII（Resource Acquisition Is Initialization，资源获取即初始化） 机制的经典范例。

    在 PyTorch 的 C++ API 中，RAII 不是用来管理内存或文件句柄，而是用来管理全局的 状态切换 ——具体来说，是控制 PyTorch 的 梯度追踪状态（GradMode）。

    其运作机制包含三个关键阶段：

    1. 构造即开启（资源获取）： 当执行 torch::NoGradGuard no_grad; 时，该对象被实例化，其构造函数会在内部自动将 PyTorch 的全局梯度追踪状态关闭。这等价于 Python 中的 with torch.no_grad(): 上下文管理器。在此之后执行的所有张量运算都不会构建计算图、不会分配梯度缓存。
    2. 生命周期绑定作用域： 该对象的作用域决定了“不记录梯度”的区间。只要 no_grad 这个变量还活着（即代码还在它所在的大括号 {} 内部），无梯度状态就会一直持续。
    3. 析构即恢复（资源释放）： 当代码执行流离开该作用域（例如函数执行结束、或者遇到 return / 异常），no_grad 对象生命周期结束并被销毁，其析构函数会自动触发，将 PyTorch 的梯度追踪状态 无条件恢复为进入该作用域之前的状态。

    为什么这种设计非常优雅？

    • 绝对的异常安全性（Exception Safety）：如果代码在作用域内部抛出了异常（如显存不足或发生崩溃），传统的“手动开关状态”可能导致状态未恢复而污染全局环境。而 RAII 依赖 C++ 的栈展开（Stack Unwinding）机制，即使发生异常，对象的析构函数也必然会被调用，从而完美恢复全局状态。
    • 代码简洁无负担：开发者不需要在代码出口处手动写清理逻辑，消除了心智负担。

    Debug 模式和 Release 模式在性能上有着天壤之别，对于涉及高强度计算的 C++ 和 CUDA 扩展而言，这种差异通常在 10 倍到上百倍 之间。

    • 编译器优化级别 (-O0 vs -O3)
      • Debug 模式 默认关闭优化（使用 -O0 标志）。编译器生成的机器码与你写的 C++ 代码严格按行对应，以便于在调试器（如 GDB）中单步跟踪。
      • Release 模式 开启高强度优化（通常使用 -O3 或 -O2）。编译器会进行激进的代码重构，包括 函数内联（Inline）、循环展开（Loop Unrolling）、常量折叠 以及 向量化指令优化，大幅减少 CPU/GPU 的指令执行周期。
    • 断言与安全检查（Assertions & Checks）
      • Debug 模式 通常会保留代码中大量的 assert() 断言、边界检查以及容器的调试宏。这些检查在每次运行时都要进行条件判断，会产生严重的性能开销。
      • Release 模式 会在编译时定义 NDEBUG 宏，直接将所有的 assert() 和调试检查在编译阶段剥离（变成空语句），做到零运行时开销。
    • 调试符号与内存布局
      • Debug 模式 会保留庞大的调试符号表（Symbol Table）和变量元数据，导致二进制文件体积暴增，甚至影响指令缓存（I-Cache）的命中率。
      • Release 模式 会剥离这些符号，使代码排布更加紧凑高效。

    const float softmax_scale = 1.0f / std::sqrt(static_cast<float>(D));

    cudaStream_t stream = c10::cuda::getCurrentCUDAStream();

    flash_attn_v2_mha_kernel<<<grid_size, block_size, smem_size, stream>>>(
        Q.data_ptr<float>(),
        K.data_ptr<float>(),
        V.data_ptr<float>(),
        O.data_ptr<float>(),
        L.data_ptr<float>(),
        N, D, BR, BC,
        softmax_scale
    );

    return std::make_tuple(O, L);
}

    2.1.1. 函数签名与返回值¶

    std::tuple<torch::Tensor, torch::Tensor> flash_attn_v2_mha_forward(
    torch::Tensor Q, 
    torch::Tensor K, 
    torch::Tensor V,
    int BR,
    int BC
)
    • 返回值变化: 返回一个包含两个张量的元组（std::tuple）：输出矩阵 O 以及在线 Softmax 所需的归一化统计量 L（FA-v2 针对反向传播或后续处理需要规范化输出）。
    • 输入参数: 同样接收 Q、K、V 以及分块大小 BR（Query 行块大小）、BC（Key/Value 列块大小）。

    2.1.2. 张量初始化（使用 torch::empty）¶

    auto O = torch::empty_like(Q);
auto L = torch::empty({B, H, N}, Q.options());
    • 这里使用 torch::empty 代替了 FA-v1 中的 torch::zeros 或 torch::full。
    • 性能考量: 因为算子内部的 CUDA Kernel 会对输出张量的每一个元素进行完整的计算和覆盖写入，先用 zeros 把显存清零是完全多余的性能浪费。empty 只分配显存空间但不初始化，能提升执行效率。

    2.1.3. 核心变革：Query 维度并行化 (num_q_blocks)¶

    const int num_q_blocks = (N + BR - 1) / BR;

// Grid: (Q 分块数, Head 数, Batch 数)
dim3 grid_size(num_q_blocks, H, B);
dim3 block_size(BR);
    • FA-v1 的局限: 在 FlashAttention-1 中，Grid 的 X 维度是 1（即 grid_size(1, H, B)），这意味着每个 Head 只有一个 Block 去串行循环处理所有的 Query 分块。当序列长度 N 较短时，GPU 的流多处理器（SM）无法被填满。
    • FA-v2 的升级: 引入了 num_q_blocks（利用向上取整公式计算出 Query 维度一共需要切分多少个块）。
    • Grid 映射: 现在的 Grid 变成了三维 (num_q_blocks, H, B)。每一个 CUDA Block 独立负责 某一个 Batch、某一个 Head、以及某一个特定的 Query 分块。这把原本串行的 Query 循环放到了 GPU 硬件网格层并行执行，大幅提升了并行度和 GPU 利用率。

    2.1.4. 共享内存（Shared Memory）精简优化¶

    size_t smem_size = (2 * BC * D) * sizeof(float);
    • 空间缩减: 相比于 FA-v1 需要同时缓存 Q、K、V 三个分块（2 * BC * D + BR * D），FA-v2 动态共享内存的大小 仅为 2 * BC * D，只用来缓存 K 和 V 的分块。
    • 原因: 因为 FA-v2 改变了内层循环的计算顺序（外层循环遍历 K/V 块，内层累加更新 Q 的结果），Q 的数据通常可以直接加载到寄存器（Registers）中，不再强制占用宝贵的 Shared Memory，从而允许使用更大的块大小（Block Size）或节省显存空间来支持更大的模型维度。

    2.1.5. 流管理与 Kernel 启动¶

flash_attn_v2_mha_kernel<<<grid_size, block_size, smem_size, stream>>>(
    Q.data_ptr<float>(),
    K.data_ptr<float>(),
    V.data_ptr<float>(),
    O.data_ptr<float>(),
    L.data_ptr<float>(),
    N, D, BR, BC,

);

return std::make_tuple(O, L);
    • 获取当前的 CUDA 流并启动 flash_attn_v2_mha_kernel。
    • 启动配置中传入了由 num_q_blocks 扩展后的 grid_size 和精简后的 smem_size，最后将计算好的 O 和辅助量 L 打包成 PyTorch 元组返回给上层。

    2.2 函数原型¶

    // FA-v2 动态 Shared Memory 多头 Attention Kernel
__global__ void flash_attn_v2_mha_kernel(
    const float* __restrict__ Q, // [B, H, N, D]
    const float* __restrict__ K, // [B, H, N, D]
    const float* __restrict__ V, // [B, H, N, D]
    float* __restrict__ O,       // [B, H, N, D]
    float* __restrict__ L,       // [B, H, N]
    const int N,
    const int D,
    const int BR,
    const int BC,
    const float softmax_scale
) {
    assert(BC < BC_MAX);
    assert(D  < D_MAX);

    const int q_block_idx = blockIdx.x; // Q 的分块索引 i
    const int head_idx = blockIdx.y;    // Head 索引
    const int batch_idx = blockIdx.z;   // Batch 索引
    const int tid = threadIdx.x;        // 线程索引 (对应 BR 内的行)
    • q_block_idx = blockIdx.x: 代表当前 Block 负责的是 Query 矩阵的第几个分块（i 块）。这是 FlashAttention-2 相比 v1 的最关键改进——将 Query 的外层循环放到了 GPU 网格层并行，极大增加了并行度，避免了 v1 中单个 Head 只能串行处理 Q 分块的性能瓶颈。
    • head_idx 和 batch_idx: 分别由 blockIdx.y 和 blockIdx.z 提供，用于定位当前任务属于哪一个 Attention Head 和哪一个 Batch。
    • tid = threadIdx.x: 当前 Block 内的一维线程局部编号（取值范围 0 到 BR-1）。由于每个 Block 的线程数配置为 BR，这里的每一个线程 tid 刚好对应负责处理当前 Q 分块中的某一行 Token。

    和V1相比，这里多了一个q_block_idx。因为我们这里是每个线程处理一行，不需要跨步循环，所以我们需要根据q_block_idx找到相对应的行。

    2.3 动态共享内存划分¶

        // 动态共享内存布局: 仅需分配 k_smem [BC * D] 和 v_smem [BC * D]
    extern __shared__ float smem[];
    float* k_smem = smem;
    float* v_smem = k_smem + BC * D;

    2.4 索引计算¶

        // 当前 Batch 与 Head 的 Memory 指针偏移计算
    const int bh_offset = (batch_idx * gridDim.y + head_idx) * N * D;
    const int bh_l_offset = (batch_idx * gridDim.y + head_idx) * N;

    const float* Q_ptr = Q + bh_offset;
    const float* K_ptr = K + bh_offset;
    const float* V_ptr = V + bh_offset;
    float* O_ptr = O + bh_offset;
    float* L_ptr = L + bh_l_offset;

    const int global_q_row = q_block_idx * BR + tid;
    • bh_offset 与 bh_l_offset（内存偏移量计算）
    • bh_offset: 将当前的 batch_idx 和 head_idx 展平，并乘以单个 Head 的总元素数 N \times D，计算出 4D 张量（Q, K, V, O）在全局内存中的起始偏移。
    • bh_l_offset: 针对形状为 [B, H, N] 的 3D 张量（如 L），因为没有 D 维度，所以只需乘以 N 计算偏移。
    • 后续的指针赋值（如 Q_ptr = Q + bh_offset）将全局基础指针移动到了当前 Head 专属的内存切片位置。
    • global_q_row（全局 Query 行索引）
      • 计算公式：q_block_idx * BR + tid。
      • q_block_idx * BR 定位到当前 Query 分块在整个大序列 N 中的起始行位置。
      • tid 是当前线程在 Block 内的局部编号（取值 0 到 BR-1）。
      • 两者相加后，global_q_row 标志着当前线程具体负责处理整个长序列中的第几个 Token。

    和前面相比，这里多了一个global_q_row，这是因为V1的内部循环跨步循环遍历所有的Q，但是V2的外部循环是加载Q。

    2.5 加载Q¶

        // FA-v2 特性 1: Q_i 直接加载到寄存器 (Register)，无需占用 Shared Memory
    float q_i[D_MAX]; // 支持最大 Head Dim 为 512
    if (global_q_row < N) {
        for (int d = 0; d < D; ++d) {
            q_i[d] = Q_ptr[global_q_row * D + d];
        }
    } else {
        for (int d = 0; d < D; ++d) {
            q_i[d] = 0.0f;
        }
    }

    由于每个线程处理Q的一行，而且相互之间没有关联，所以可以把共享内存改成寄存器。不过这样实现是有问题的，q_i并没有放到寄存器，后面我们再来讨论这个问题，这里就暂且认为它是放到寄存器里。

    2.6 初始化O,l和m¶

        // 在寄存器中初始化状态变量 (FA-2 算法 Line 5)
    float O_i[D_MAX] = {0.0f};
    float l_i = 0.0f;
    float m_i = -FLT_MAX;

    2.7 循环加载K和V¶

        // 内层循环：遍历 K_j, V_j 分块 (FA-2 算法 Line 6)
    for (int j = 0; j < Tc; ++j) {

        // 协同加载 K_j, V_j 到 Shared Memory
        for (int row = tid; row < BC; row += blockDim.x) {
            const int global_k_row = j * BC + row;
            if (global_k_row < N) {
                for (int d = 0; d < D; ++d) {
                    k_smem[row * D + d] = K_ptr[global_k_row * D + d];
                    v_smem[row * D + d] = V_ptr[global_k_row * D + d];
                }
            } else {
                for (int d = 0; d < D; ++d) {
                    k_smem[row * D + d] = 0.0f;
                    v_smem[row * D + d] = 0.0f;
                }
            }
        }
        __syncthreads();

    2.8 计算S_{ij}¶

                // 计算 S_i^{(j)} = Q_i * K_j^T * scale
            float S_i_j[BC_MAX]; // 假设 BC <= 256
            float rowmax_S = -FLT_MAX;

            for (int col = 0; col < BC; ++col) {
                const int global_k_row = j * BC + col;
                if (global_k_row < N) {
                    float score = 0.0f;
                    for (int d = 0; d < D; ++d) {
                        score += q_i[d] * k_smem[col * D + d];
                    }
                    score *= softmax_scale;
                    S_i_j[col] = score;
                    rowmax_S = fmaxf(rowmax_S, score);
                } else {
                    S_i_j[col] = -FLT_MAX;
                }
            }

    2.9 计算\tilde{P}_{ij}和rowsum(\tilde{P}_{ij})¶

                // 在线更新 Max 与 Exp Sum (FA-2 算法 Line 9)
            float m_i_prev = m_i;
            float m_i_j = fmaxf(m_i_prev, rowmax_S);

            float P_tilde_j[BC_MAX];
            float rowsum_P_tilde = 0.0f;

            for (int col = 0; col < BC; ++col) {
                const int global_k_row = j * BC + col;
                if (global_k_row < N) {
                    P_tilde_j[col] = expf(S_i_j[col] - m_i_j);
                    rowsum_P_tilde += P_tilde_j[col];
                } else {
                    P_tilde_j[col] = 0.0f;
                }
            }

    2.10 计算\ell_i^{(j)}¶

                float alpha = expf(m_i_prev - m_i_j);
            float l_i_j = alpha * l_i + rowsum_P_tilde;

    2.11 计算O_i^{(j)}¶

                // FA-v2 特性 2: 延迟归一化，仅对寄存器中的 O_i 进行 Rescale Scaling (Line 10)
            for (int d = 0; d < D; ++d) {
                float p_v = 0.0f;
                for (int col = 0; col < BC; ++col) {
                    p_v += P_tilde_j[col] * v_smem[col * D + d];
                }
                O_i[d] = alpha * O_i[d] + p_v;
            }

    2.12 一次性写回HBM¶

        // 循环结束后统一进行除以 sum 的最终归一化 (FA-2 算法 Line 12-15)
    if (global_q_row < N) {
        float inv_l_i = (l_i > 0.0f) ? (1.0f / l_i) : 0.0f;
        for (int d = 0; d < D; ++d) {
            O_ptr[global_q_row * D + d] = O_i[d] * inv_l_i;
        }

        if (L != nullptr) {
            L_ptr[global_q_row] = m_i + logf(l_i);
        }
    }

    2.13 使用Pytorch的矩阵乘法实现MLA¶

    // 修改返回值类型为 std::optional，发生异常时返回 std::nullopt
std::optional<std::tuple<torch::Tensor, torch::Tensor>> pytorch_mha_ref(
    torch::Tensor Q, 
    torch::Tensor K, 
    torch::Tensor V
) {
    try {
        const float scale = 1.0f / std::sqrt(static_cast<float>(Q.size(-1)));

        torch::Tensor S = torch::matmul(Q, K.transpose(-2, -1)) * scale;
        torch::Tensor O = torch::matmul(torch::softmax(S, -1), V);
        torch::Tensor L = torch::logsumexp(S, -1);

        return std::make_tuple(O, L);
    } 
    catch (const c10::OutOfMemoryError& e) {
        std::cerr << "\n[PyTorch MHA OOM Warning] 显存不足！" << std::endl;

        // 清理缓存以释放未使用的显存碎片，保障后续算子能继续执行
        c10::cuda::CUDACachingAllocator::emptyCache();
        return std::nullopt;
    } 
    catch (const c10::Error& e) {
        std::cerr << "\n[PyTorch MHA Error] " << e.msg() << std::endl;
        return std::nullopt;
    }
}

    这里除了计算O，还计算了LogSumExp的L。另外我们还捕获了OutOfMemoryError，因为测试的时候我们会演示这一点。
