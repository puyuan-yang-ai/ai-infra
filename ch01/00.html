    GPU发展史¶

    学习目标¶

    • 了解GPU的发展历史
    • 理解GPU的发展趋势

    1. 前 GPU 时代——专用协处理器与固定管线（1980s - 1990s）¶

    1.1. 硬件催生：多媒体与 3D 图形的萌芽¶

    • CPU 的力不从心： 早期的个人电脑中，所有计算（包括显示输出、音频、系统逻辑）全由 CPU 独揽。面对早期的 3D 游戏（如《Doom》、《Quake》）以及 CAD 工业绘图，CPU 处理海量像素的空间几何变换（矩阵运算）时成为严重瓶颈。
    • 图形协处理器（Graphics Coprocessor）的诞生： 80 年代中后期，市场上出现了专门协助 CPU 处理特定图形任务的芯片（如 TI TMS34010）。此时它们还被称为“显卡”或“图形加速器”，功能单一，多用于 2D 位图移动或简单的线框渲染。

    1.2. 固定功能管线（Fixed-Function Pipeline）的统治¶

    • 硬编码的艺术： 1990 年代中后期，以 3DFX 公司的 Voodoo 显卡为代表，行业进入 3D 加速卡黄金时代。这一时期的微架构被称为“固定管线”。
    • 底层机制： 几何变换、光照计算（T&L）、纹理映射和光栅化等图形算法被直接硬编码（Hard-wired）在硅片电路中。
    • 开发局限： 开发者无法修改硬件的计算行为。这就好比一个智能开关箱，应用层（通过早期的 OpenGL 或 DirectX 1.0~7.0）只能选择“开启或关闭某种光照模式”，或者调整预设的参数，无法实现个性化的视觉特效。
    • GPU 概念的正式确立： 1999 年，NVIDIA 发布 GeForce 256，首次将几何变换和光照引擎（T&L）完整集成到单颗芯片上，并正式将其命名为 GPU（Graphics Processing Unit），图形芯片正式脱离“CPU 协处理器”的附庸地位，成为独立计算核心。

    1.3 GPU vs 图形加速卡¶

    在 NVIDIA 于 1999 年发布 GeForce 256 之前，市面上的图形芯片（通常被称为“图形加速器”或“3D 加速卡”，如著名的 3DFX Voodoo 系列）与 GeForce 256 存在着本质上的微架构差异。

    最核心的区别可以用一句话概括：GeForce 256 之前的芯片只负责渲染管线的后半段（像素填充）；而 GeForce 256 首次将整个图形管线（几何计算+像素填充）完整地集成到了单颗芯片上。

    以下是具体的对比和深层技术区别：

    1.3.1. 计算职责的划分（CPU 的解放程度不同）¶

    3D 图形渲染管线在早期主要分为两个核心阶段：

    1. 几何与光照阶段（T&L - Transform and Lighting）： 负责处理三维空间中物体的顶点坐标旋转、平移、缩放（矩阵变换），以及计算光源照射在物体表面产生的亮度和色彩。这涉及大量的 浮点数矢量运算。
    2. 光栅化与像素渲染阶段（Rasterization & Pixel Processing）： 负责把三维的几何图形“拍扁”成二维屏幕上的像素，并进行纹理贴图、色彩混合和着色。
    • GeForce 256 之前（如 Voodoo 2）：
      • 芯片角色： 只是一个 半程加速器。
      • CPU 负担： 所有的 T&L（几何与光照）计算全部由主板上的 CPU（如 Intel Pentium II/III）用软件算法完成。CPU 算好顶点的二维屏幕坐标后，通过极其狭窄的系统总线（如 PCI 或早期的 AGP 1X/2X）将这些顶点数据“喂”给 3D 加速卡。
      • 显卡职责： 仅仅负责后半段的 光栅化、纹理贴图和像素填充。如果当年你的 CPU 性能不够强，即使买了两块 Voodoo 显卡组 SLI，游戏依然会严重卡顿，因为 CPU 几何计算成为了系统瓶颈。
    • GeForce 256 时代：
      • 芯片角色： 完整的 独立中央图形处理器。NVIDIA 首次在硅片上硬编码了一个 硬件 T&L 引擎（Hardware T&L Engine）。
      • 完全解放 CPU： CPU 只需要把游戏逻辑、物体的原始三维模型数据发送给显卡，所有的空间矩阵变换、光照强度计算全部由 GeForce 256 芯片内部的硬件电路独自完成。这直接让系统内的图形浮点计算吞吐量提升了数倍，CPU 得以解脱去处理更复杂的算法（如游戏 AI、物理碰撞）。

    1.3.2. 硬件定位与术语的定义¶

    • GeForce 256 之前：
      • 行业内称呼它们为 3D Accelerator（3D 加速卡） 或 Graphics Coprocessor（图形协处理器）。
      • 它们的定位更接近于早期的“数学协处理器（如 80387）”，是 CPU 的一个 外挂挂件。没有 CPU 的实时在线伺候，它们连一个三角形都画不出来。甚至像早期的 Voodoo 1/2 连 2D 显示功能都没有，必须用一根外部跳线连接到普通的 2D 显卡上才能正常工作。
    • GeForce 256 时代：
      • NVIDIA 正式发明并定义了 GPU（Graphics Processing Unit，图形处理器） 这个词。
      • NVIDIA 对其的官方定义是：“单芯片处理器，集成了变换（Transform）、光照（Lighting）、三角形设置/裁剪（Setup/Clip）和渲染（Render）引擎，每秒至少能处理 1000 万个多边形。”
      • 从这一刻起，GPU 获得了与 CPU 平起平坐的独立处理器（Processor）地位。

    1.3.3. 数据传输的瓶颈（总线依赖度）¶

    • GeForce 256 之前：
      • 由于 T&L 由 CPU 计算，CPU 必须将计算出的每一帧成千上万个顶点的坐标、颜色、纹理坐标源源不断地实时传输给加速卡。这导致 系统总线（PCI / AGP 接口）成为了致命的交通堵塞点。数据传输的延迟极大地限制了游戏画面的多边形数量（当年游戏模型看起来都非常“方”，棱角分明，就是因为多边形不敢做得太多）。
    • GeForce 256 时代：
      • 由于硬件 T&L 移到了 GPU 内部，CPU 只需要在关卡加载时或者每帧发送少量的模型控制参数和状态指令，海量的顶点交互和几何计算全部在 GPU 内部的高速显存和芯片通路间完成。这绕过了总线带宽瓶颈，使得游戏画面的多边形数量呈指数级爆发（场景和人物变得极其圆润、逼真）。

    2. 可编程革命——现代 GPU 的架构奠基（2001 - 2006）¶

    2.1. 分离着色器架构（Separated Shader Architecture）¶

    • 把控制权还给软件： 随着好莱坞级电影特效（如逼真的水波、皮肤折射）的需求倒逼，固定的硬件电路走向终结。2001 年，微软在 DirectX 8 中引入了可编程着色器（Shader）概念。
    • 微架构的分工： 此时的 GPU 内部被划分为两组截然不同、功能不互通的计算单元：
      • 顶点着色器（Vertex Shader）： 专门运行顶点的空间变换、多边形设置代码。
      • 像素/片元着色器（Pixel/Fragment Shader）： 专门运行计算屏幕上每个像素最终颜色的代码。

    2.2. 致命缺陷：结构性负载不均（Load Imbalance）¶

    • 晶体管的极大浪费： 在实际的游戏或渲染场景中，复杂几何体多的场景（如满屏复杂的立体建模，但涂色简单）会导致顶点单元爆满、像素单元闲置；反之，大面积光影特效的场景（如漫天大雪、水面反光，但模型简单）则会导致像素单元不堪重负、顶点单元无所事事。这种物理结构上的划分，限制了硬件吞吐量的进一步提升。

    2.3. 统一着色器架构（Unified Shader Architecture）¶

    • 破壁者 G80 架构： 2006 年，NVIDIA 发布了划时代的 G80 架构（GeForce 8800 GTX），彻底打破了顶点和像素的物理隔离。
    • 流处理器（SP / CUDA Core）的诞生： G80 取消了专用单元，引入了统一的、通用的、可编程的计算核心。
    • 动态调度机制： 硬件调度器根据当前的渲染任务负载，动态决定将这些核心用于处理顶点还是像素。硬件利用率逼近 100%，这不仅是图形学的飞跃，更是通用计算（GPGPU）的物理基础。

    3. GPGPU 与生态纪元——数据并行计算的崛起（2006 - 2016）¶

    3.1. 软件层面的“黑客”突围¶

    • 在 2006 年之前，少数科学家意识到 GPU 的并行浮点计算能力远超 CPU，尝试用它算矩阵或偏微分方程。
    • 极其痛苦的映射（Mapping）： 当时的显卡不认数学公式，科学家必须将“矩阵数据”伪装成“2D 纹理贴图”，将“矩阵乘法”伪装成“像素混色着色器”，计算完成后再从“帧缓冲区”读取结果。这种反人类的开发方式让非图形学专家望而生畏。

    3.2. CUDA 的惊天一赌与 SIMT 拓扑结构¶

    • 软硬一体化： 2006 年底，黄仁勋在 G80 硬件中塞入了通用的执行控制逻辑，并推出了 CUDA（Compute Unified Device Architecture） 编程模型及 C 语言扩展。
    • SIMT（单指令多线程）模型确立：
      • CUDA 抽象出了网格（Grid）、线程块（Block）、线程（Thread）的层次拓扑。
      • 硬件上引入了线程束（Warp）和共享内存（Shared Memory）。
      • 开发者终于可以直接写 __global__ void matMul() 这样的矩阵函数，彻底告别了图形学的黑话。
    • 历史意义： 这一战略让 NVIDIA 背负了数年巨大的晶体管成本和研发亏损，但成功建立起了至今无法被打破的软件生态壁垒。

    CUDA 之所以让当时的 NVIDIA 背负了巨大的晶体管成本和沉重的研发亏损，主要有以下四个深层硬件与商业原因：

    3.2.1. 极其昂贵的“硬件隐形成本”：强行在消费级芯片中塞入通用控制逻辑¶

    在 2006 年，NVIDIA 的主要收入来源依然是卖游戏显卡（GeForce 系列）。如果只为了让游戏跑得快，芯片只需要堆砌纯粹的图形渲染单元即可。

    但是，黄仁勋为了实现“通用计算（GPGPU）”，强制要求 NVIDIA 生产的所有芯片（无论是给服务器用的，还是卖给普通玩家的游戏卡、笔记本显卡）都必须完整硬件支持 CUDA。

    • 晶体管的严重浪费： 为了支持 CUDA 的 SIMT（单指令多线程）执行模型、线程调度、状态保存以及支持更高级的 IEEE 754 浮点数标准，NVIDIA 必须在芯片内部额外塞入庞大的 执行控制逻辑、寄存器堆、硬件调度器（Warp Scheduler）以及共享内存（Shared Memory）。
    • 芯片面积（Die Size）暴增： 这些为了通用计算准备的硬件结构，对当时的游戏毫无帮助，却占用了大量的芯片面积（晶体管）。
    • 成本与良率的双重打击： 芯片面积越大，在一整块晶圆上切出的合格芯片就越少，制造成本呈指数级上升。NVIDIA 用极高的硬件成本造出芯片，却只能以普通游戏卡的价格卖给玩家（因为当时 99% 的买家根本不用 CUDA）。这意味着 NVIDIA 在用游戏业务的利润，疯狂补贴这些“毫无用处”的硬件晶体管。

    3.2.2. 软件生态是吞噬资金的“无底洞”¶

    硬件造出来只是第一步，要让科学家放弃 CPU 转向写 CUDA，NVIDIA 必须提供全套的、极其好用的软件工具链。

    • 研发团队的疯狂扩张： 软件开发和硬件开发完全不同，NVIDIA 招聘了成千上万的高薪软件工程师、编译器专家和数学家。他们从零开始手写 C/C++ 编译器（nvcc）、调试器（cuda-gdb）、性能分析工具（Visual Profiler）。
    • 底层数学库的无偿投入： 为了吸引科研界，NVIDIA 组织了顶尖的数学家团队，一行行代码手写并优化出 cuBLAS（基础线性代数库）、cuFFT（快速傅里叶变换库） 等底层数学核心算子。这些庞大的软件生态在当时是 完全免费 提供给业界的，短期内根本没有任何商业回报。

    3.2.3. 市场是一片荒漠，几乎“零收入”¶

    在 2006 到 2012 年长达六年的时间里，人工智能（深度学习）还没爆发，大模型更是不存在。

    • 当时世界上需要用到高性能通用计算（HPC）的客户极少，只有少数高校气象研究所、石油勘探公司或国家实验室。
    • NVIDIA 专门针对企业级高性能计算推出的 Tesla 产品线 在初期销量惨淡，根本无法收回前期恐怖的研发成本。NVIDIA 陷入了 硬件高成本亏本卖、软件高投入免费送、核心市场又尚未诞生 的恶性循环。

    3.2.4. 资本市场的极度不理解与看空¶

    当时华尔街的分析师普遍认为黄仁勋疯了。资本市场的逻辑非常现实：

    • AMD（通过收购 ATI）正在通过推出纯粹、轻量、高性价比的游戏显卡来蚕食 NVIDIA 的市场份额。
    • 分析师们纷纷指责 NVIDIA 放弃了原本高利润率的游戏本行，去追求一个虚无缥缈的“通用计算”梦。这种巨大的战略分歧导致 NVIDIA 的财报连续几个季度极度难看，研发费用率（R&D 占营收比重）飙升，直接引发了华尔街的做空，企业现金流一度极度紧张。

    3.3. 深度学习的奇点（2012）¶

    • AlexNet 的火花： 2012 年，Alex Krizhevsky 使用两块 NVIDIA GTX 580 显卡和手写的 CUDA 卷积算子，在 ImageNet 图像识别大赛中以压倒性优势夺冠。
    • 时代的交棒： 全球科技界猛然醒悟：GPU 的海量数据并行架构，天然就是为了神经网络的矩阵乘法而生的。GPU 从“游戏加速卡”正式转型为“AI 战略物资”。

    4. 领域特定架构（DSA）演进——矩阵计算与 AI 算力大爆发（2017 - 2023）¶

    随着摩尔定律放缓，单纯增加通用 CUDA Core 的边际效应开始递减，GPU 架构引入了领域特定（Domain-Specific）的硬编码专用加速单元，形成了“通用中有专用”的现代结构。

    演进阶段 / 架构 代表产品 核心技术变革（DSA 引入） 计算范式转移
    Volta 架构 (2017) V100 首代 Tensor Core（张量核心） 诞生 从传统的 矢量计算（Vector） 转向专门的 4 \times 4 矩阵计算（Matrix），AI 吞吐量暴增。
    Ampere 架构 (2020) A100 TF32 精度支持与结构化稀疏（Sparsity） 引入硬件级稀疏化技术（2:4 稀疏），在不损失精度的情况下使 AI 计算吞吐量直接翻倍。
    Hopper 架构 (2022) H100 Transformer Engine & DPX 指令 动态调整 FP8 和 FP16 混合精度；硬件级加速 Transformer 架构中的 Softmax 和 Attention 算子。

    5. 现代异构与万卡集群时代——多芯、多维度的系统级计算（2024 至今）¶

    今天的 GPU 已经不再是单颗芯片（Single-Die）的竞争，而是进化为了融合了 先进封装、统一内存、超高速互联的网络化系统。

    5.1. 从单片（Monolithic）到芯粒（Chiplet/MCM）¶

    • 物理极限的突破： 光刻机屏蔽尺寸（Reticle Limit）限制了单颗芯片的面积上限。为了追求更高的算力，各大厂商全面转向 MCM（多芯片封装）。
    • 代表技术： AMD Instinct MI300X、NVIDIA Blackwell (B200)。通过将多颗计算芯粒、HBM3e 显存利用台积电 CoWoS 3D 封装技术“胶水”在一起，让上百亿晶体管在逻辑上表现为一颗超大型 GPU。

    5.2. 异构计算的终极形态：CPU + GPU 深度融合¶

    • 打破 PCIe 的内存壁垒（Memory Wall）： 传统架构中，数据在 CPU 内存（DDR）和 GPU 显存（VRAM）之间通过狭窄的 PCIe 总线复制，延迟高、带宽低。
    • 超高速缓存一致性互联：
      • NVIDIA GB200 (NVL72)： Grace CPU 与 Blackwell GPU 通过 NVLink-C2C 互联，带宽高达 900 GB/s。CPU 和 GPU 共享统一的虚拟内存地址空间。
      • AMD MI300A： 将 24 个 Zen4 CPU 核心、CDNA3 GPU 核心和 HBM 显存集成在同一套封装内，实现真正的 主存级异构融合。

    5.3. “The Network is the Computer” —— 网络即计算¶

    • 从单卡到集群： 面对千亿、万亿参数的大型多模态模型（MLLM），单颗 GPU 的显存和算力只是沧海一粟。现代 AI Infra 的核心在于 集群级异构。
    • NVLink 交换机（NVLink Switch）与 InfiniBand 技术： 几万颗 GPU 通过高达数 TB/s 的互联网络连成一体。通过 Tensor Parallelism (TP)、Pipeline Parallelism (PP) 等分布式并行技术，整个数据中心在软件视角下，正变成一台巨大无比的“巨型异构计算机”。

    6. Nvidia显卡的命名¶

    基于 NVIDIA 过去二十多年的战略转型，其显卡产品线的命名和分类经历了从“纯粹的游戏显卡” 到 “开启通用计算的双产品线时代”，再到如今 “消费级与数据中心级彻底划江而治”的巨大变革。

    6.1 第一阶段：单兵作战时代（1999 - 2006）¶

    在 CUDA 诞生之前，NVIDIA 的绝对主力就是游戏显卡。

    • 核心品牌：GeForce 系列
      • 定位： 纯粹的消费级/游戏显卡。
      • 代表架构与产品： Fahrenheit 架构（GeForce 256）、Kelvin 架构（GeForce 3/4）、Rankine 架构（GeForce 5/FX 系列）、Curie 架构（GeForce 6/7 系列）。
      • 特点： 这一时期的显卡全是以游戏画面渲染、像素填充率（Fillrate）为核心指标。
    • 分支衍生：Quadro 系列
      • 定位： 专业工作站显卡。
      • 特点： 硬件本质上与 GeForce 相同，但通过特定的驱动程序优化和固件锁，专门用于加速 AutoCAD、Maya、3DMax 等工业 3D 绘图软件，价格高昂。

    6.2 第二阶段：双线并行与 Tesla 的诞生（2006 - 2019）¶

    2006 年 G80 架构（Tesla 架构）发布，统一着色器架构与 CUDA 的问世打破了格局。黄仁勋为了开拓高性能计算（HPC）和企业级市场，正式开辟了全新的产品线。

    6.2.1. 消费级市场：延续 GeForce 命名¶

    • 品牌： GeForce GTX / GT
    • 架构演进： Tesla 架构 (8800GTX) \rightarrow Fermi 架构 (GTX 480/580) \rightarrow Kepler 架构 (GTX 680/780) \rightarrow Maxwell 架构 (GTX 980) \rightarrow Pascal 架构 (GTX 1080/1080Ti)。
    • 特点： 尽管硬件上支持 CUDA，但主要卖点依然是 Direct3D/OpenGL 游戏性能。

    6.2.2. 企业/计算级市场：Tesla 产品线问世（GPGPU 的起点）¶

    • 品牌： NVIDIA Tesla
    • 定位： 去图形化、纯计算显卡（Data Center & HPC）。
    • 命名逻辑： 架构代号首字母 + 型号。例如：
      • Fermi 架构：Tesla M2090/C2075
      • Kepler 架构：Tesla K40 / K80 （K80 是经典的单卡双核计算卡）
      • Maxwell 架构：Tesla M40 / M4
      • Pascal 架构：Tesla P100 / P40 （P100 首次引入了 HBM2 显存和第一代 NVLink 互联）
    • 革命性转折（AI 爆发）：Volta 架构 (2017) 与 Tesla V100
      • Volta 架构没有大规模推向普通游戏市场，而是专注于计算。Tesla V100 首次引入了 Tensor Core（张量核心），成为全球深度学习训练的黄金标准。
    • 消费级阵营的异动（2018）：RTX 的诞生（Turing 架构）
      • 2018年，NVIDIA 在消费级（GeForce）引入光线追踪技术（RT Core）和用于 DLSS 的 Tensor Core。消费级显卡前缀正式从 GTX 变更为 RTX（如 RTX 2080 Ti）。

    6.2.3 第三阶段：去 Tesla 化与现代“划江而治”时代（2020 至今）¶

    到了 2020 年 Ampere 架构 发布时，发生了一个非常有趣的品牌更名事件：NVIDIA 决定彻底停用 “Tesla” 这个品牌名。

    • 原因： 官方给出的理由是避免与马斯克的“特斯拉（Tesla）汽车”产生严重的商标混淆与联想。
    • 更名策略： 原本应该被称为“Tesla A100”的产品，直接被更名为 NVIDIA A100 Tensor Core GPU。自此，计算卡产品线统一归入 “NVIDIA Data Center（数据中心）” 门类。

    现代的产品线划分已经非常清晰，消费级与数据中心级在架构、命名和硬件设计上彻底分家：

    6.2.3.1. 现代消费级/工作站产品线¶

    • 品牌： NVIDIA GeForce RTX（游戏） 和 NVIDIA RTX（原 Quadro 系列更名，去掉了 Quadro 字母，直接叫 NVIDIA RTX A6000 / RTX 6000 Ada）。
    • 架构与命名：
      • Ampere 架构：RTX 30 系列（如 RTX 3090）
      • Ada Lovelace 架构：RTX 40 系列（如 RTX 4090）
    • 特点： 保留显示输出接口（HDMI/DP），拥有极高的时钟频率，主攻图形、游戏、实时光追以及轻量级本地 AI 开发。

    6.2.3.2. 现代数据中心/AI 计算产品线¶

    • 品牌： NVIDIA 数据中心 GPU（直接以架构首字母 + 数字命名，没有多余的前缀品牌名）
    • 架构与命名：
      • Ampere 架构 (2020)：NVIDIA A100 / A800 / A30
      • Hopper 架构 (2022)：NVIDIA H100 / H200 / H800 / H20（H200 首次搭载 HBM3e，专攻超大模型）
      • Blackwell 架构 (2024+)：NVIDIA B100 / B200 / GB200
    • 特点： 彻底取消物理显示接口，不再具备图形输出能力。不采用普通的 PCIe 插槽形态，而是大量采用 SXM 模组 形态。堆砌恐怖的 HBM 高带宽显存，完全为了超大规模分布式大模型训练（万卡集群）和高并发推理而生。

    总结：NVIDIA 核心产品线命名演进表¶

    时代 / 架构 消费级/游戏卡命名 (GeForce) 数据中心/高性能计算卡命名 (HPC / AI) 核心战略与产品线特征
    G80 时代 (2006) GeForce 8800 GTX Tesla C870 / D870 (首次出现) 产品线一分为二。 消费级做游戏，Tesla 线开启 GPGPU 探索。
    Fermi / Kepler (2010-2013) GeForce GTX 480 / 780 Ti Tesla M2090 / K40 / K80 Tesla 产品线进入国家超算中心和石油勘探领域。
    Pascal / Volta (2016-2017) GeForce GTX 1080 Ti Tesla P100 / V100 深度学习奇点。 V100 引入 Tensor Core，AI 训练需求彻底压倒传统 HPC。
    Ampere (2020) GeForce RTX 3090 NVIDIA A100 (废除 Tesla 称谓) 正式更名。 消费级全面进入 RTX 时代；计算卡去掉 Tesla，直接归为数据中心卡。
    Hopper / Blackwell (2022-2026) GeForce RTX 4090 / 5090(预测) NVIDIA H100 / H200 / B200 大模型与系统级异构。 两条线在物理形态、显存介质（GDDR vs HBM）和价格上彻底天差地别。

    7. 不能做图形渲染的“显卡”？¶

    我很有钱，能不能买一块H100“显卡”去打游戏？

    7.1. 物理层面的“不能渲染”：取消视频输出接口（2012年 Kepler 架构开始）¶

    从 2012 年的 Tesla K40 / K80 开始，NVIDIA 的纯计算卡在外观上就发生了一个巨大的变化：它的挡板上变成了光秃秃的一片，没有任何 HDMI、DisplayPort 或 DVI 接口。

    • 技术逻辑： 既然它是被插在机房服务器里的，它的任务就是计算，算完的数据通过 PCIe 总线或 NVLink 传回给 CPU、网络或者存入硬盘。它不需要直接驱动任何物理显示器，因此砍掉视频输出接口可以节省挡板空间用于散热（服务器通常采用前后通风格风扇）。
    • 如何渲染？ 这时的卡依然拥有图形渲染的硅片电路，只是它只能做“离线渲染（Offline Rendering）”或“无头渲染（Headless Rendering）”。例如，好莱坞特效公司用这些卡渲染电影动画，或者云游戏服务器用它在后台渲染好游戏画面，再通过网络把画面像素流推送到用户的手机或电脑上。

    7.2. 微架构层面的“彻底去图形化”：Volta 架构的惊天一划（2017 年）¶

    真正让计算卡在底层微架构上与图形渲染“划清界限”的，是 2017 年发布的 Volta 架构（Tesla V100）。

    在 Volta 之前（如 Pascal 架构的 Tesla P100），计算卡虽然去掉了接口，但它的底层核心（SM 单元）里依然保留了专门用于游戏图形渲染的硬件——比如 光栅化引擎（Raster Engine）、纹理映射单元（TMUs）以及 ROPs（光栅化输出单元）。

    • Volta（V100）的激进变革： 黄仁勋为了给 AI 腾出每一平方毫米的晶体管空间，在设计 V100 芯片时，大幅度精简或在某些专用计算计算核中阉割了传统图形渲染所需的硬件管线，取而代之的是塞入了大量的 Tensor Core（张量核心）。
    • 如果你强行用 V100 去跑当年的 3D 游戏，你会发现它的表现非常糟糕，甚至可能不如一张千元级的 GeForce 游戏显卡。因为它的硬件结构完全不是为了画三角形、贴纹理而设计的。

    7.3. 生态与驱动层面的“划江而治”（2020 年 Ampere 架构至今）¶

    到了今天的 Hopper 架构（H100/H200）和 Blackwell 架构（B100/B200），NVIDIA 在官方定位上已经完全将它们定义为 “Tensor Core GPU” 或 “AI 加速器”，连“显卡（Graphics Card）”这个词都不再使用了。

    • 驱动层面的封锁： NVIDIA 在底层驱动上将这些卡与 Direct3D、OpenGL 等游戏图形 API 彻底解绑。你无法在 H100 上安装 GeForce 游戏驱动，它只认数据中心专用的 CUDA 计算驱动。
    • 如果现代数据中心需要做图形渲染怎么办？ NVIDIA 并没有让 H100 去做这个工作，而是专门划分了一条“数据中心图形/万能加速卡”产品线（比如 NVIDIA A10/L4/L40S）。这些卡采用的并不是 Hopper 这种纯 AI 架构，而是采用了与游戏卡同源的 Ada Lovelace 架构，它们不仅支持 CUDA，内部还完整保留了 RT Core（光线追踪核心） 和图形管线，专门用来应对云游戏、元宇宙（Omniverse）、3D 虚拟主播和 3D 工业仿真等需要“图形+AI”的异构场景。

    总结¶

    • 开始没有显示接口（物理不能接显示器）： 2012 年的 Tesla K 系列。
    • 微架构底层精简图形单元（硬件不适合渲染）： 2017 年的 Tesla V100（Volta 架构）。
    • 完全转职为 AI 算力集群（软件和定位上彻底脱离图形）： 2020 年的 A100（Ampere 架构） 及其后续的 H100、B200。

    8. 为什么游戏卡可以做通用计算？¶

    计算卡不给显示接口阻断了它去打游戏、做普通渲染的路；但游戏卡却完整保留了算力核心，可以用来做模型推理和轻量训练。”

    这种看似“不对等”的硬件阉割与开放，背后隐藏着 NVIDIA 极其高明的 商业闭环逻辑、价格歧视策略 以及对 开发者生态的全面垄断。

    8.1. 终极的价格歧视与利润最大化¶

    这是最直接的商业利益考量。

    • 如果计算卡保留图形接口： 很多网吧、游戏工作室、或者高端玩家就会去抢购淘汰的或企业级的高端计算卡来打游戏。这会严重冲击 NVIDIA 利润空间巨大的 GeForce 消费级高阶市场。
    • 为什么允许游戏卡做推理？
      • 因为游戏卡有 物理规格的“天然物理外挂”——显存（VRAM）带宽和容量的限制。
      • 大模型的推理和训练是极其吃显存容量和显存带宽的（Memory-Bound）。游戏卡（如 RTX 4090）使用的是 GDDR6X 显存，带宽在 1 TB/s 左右，容量上限被死死限制在 24GB。而企业级计算卡（如 H100、H200）使用的是 HBM3/HBM3e 显存，带宽高达 3.5 TB/s ~ 4.8 TB/s，容量动辄 80GB、141GB。
      • NVIDIA 的算盘是： 你可以用 4090 在家跑本地部署、玩 8B/70B 的量化小模型，因为 24GB 显存是你的天花板。但如果你是商业公司，想要在线上为几百万用户提供高并发的 LLM 推理服务，或者想要训练千亿参数的大模型，游戏卡的显存和 PCIe 带宽（不支持大规模 NVLink 互联）会让你痛苦到死，你 必须 乖乖掏出几十倍的溢价去买几万美元一卡的 H100/B200。

    8.2. 本地部署（Local Deployment）与端侧 AI 的战略卡位¶

    允许游戏卡做模型推理，是 NVIDIA 对未来 “端侧 AI（Edge AI）”和“本地部署” 趋势的绝对卡位。

    • 占领每一个人的桌面： 并不是所有的 AI 任务都需要上传到云端。隐私保护（如本地个人助理、企业本地知识库）、低延迟（如 AI 实时语音、游戏内 AI 智能 NPC、画师本地 Stable Diffusion 绘图）都强烈依赖本地部署。
    • 硬件基础： 全球有数以亿计的电脑安装了 NVIDIA 的 GeForce RTX 显卡。这意味着 NVIDIA 在不需要任何额外投资的情况下，在一夜之间将全球数亿台 PC 变成了潜在的“本地 AI 推理机”。
    • 微软力推的 Copilot+ PC 概念以及各种本地大模型客户端（如 Ollama、LM Studio），默认优化最好的就是 NVIDIA 的 RTX 显卡。这种无处不在的硬件基础，让任何竞争对手（如 Intel、AMD 或苹果的 Mac）在端侧 AI 爆发时都很难撼动 NVIDIA 的统治地位。

    8.3. 生态的“蝇子草策略”：培育源源不断的开发者¶

    世界上最顶尖的 AI 科学家、算法工程师、高校学生，在他们还没有进入大型大厂、还没有权限调度机房里的万卡集群之前，他们是在哪里写出第一行 CUDA 代码、训练第一个玩具模型的？

    答案是：在他们自己的、装有 GeForce RTX 显卡的个人电脑或实验室工作站上。

    • 降低学习门槛，锁死生态： 如果 NVIDIA 规定游戏卡不能做推理和计算，那么全世界的高校学生和初学者就必须租用昂贵的云端 GPU 才能学习 AI 编程。这会直接把大量开发者推向竞争对手（比如去用 CPU 跑 OpenVINO，或者用 Mac 的统一内存跑 Apple Silicon 优化）。
    • NVIDIA 故意让游戏卡拥有完美的 CUDA 和 Tensor Core 支持，就是为了让所有人在学生时代、在独立开发者阶段，就深度习惯于 “写 AI 代码 = 调用 CUDA”。
    • 当这些学生毕业、开发者创业，进入大厂拥有几亿预算购买数据中心设备时，他们的本能反应必然是购买 NVIDIA 的计算卡，因为他们熟悉的整套代码工具链（PyTorch、TensorRT、Triton）在 NVIDIA 硬件上跑得最顺畅。游戏卡成了计算卡最好的“免费体验版”和“生态播种机”。

    8.4. 商业应用的“开发机”与“生产线”解耦¶

    在工业界，大模型的落地流程通常是：

    1. 研发与原型阶段（Development）： 工程师在本地用一张 RTX 4090 显卡调试算子、微调一个小型的 Embedding 模型、或者跑通 RAG（检索增强生成）的 Pipeline 流程。这个阶段不需要高并发，24GB 显存的游戏卡绰绰有余。
    2. 全量生产阶段（Production）： 当算法跑通，需要部署到线上面对海量并发请求，或者需要用海量数据做千亿大模型全量预训练时，团队会无缝地将这套代码迁移到云端或机房的 H100/H200/B200 集群上。

    这种“开发在消费级，生产在数据中心”的无缝衔接，构成了现代 AI Infra 最完美的工程闭环。

    总结¶

    计算卡和游戏卡的这种功能设定，是一场精妙的商业算计：

    “用高筑的物理壁垒（无接口、高售价）防止企业客户‘向下薅羊毛’用便宜卡替代昂贵卡；同时用完全开放的算力壁垒（支持推理、低门槛）吸引海量开发者‘向上做贡献’，将整个 AI 世界的底层代码死死绑定在自己的生态里。”
